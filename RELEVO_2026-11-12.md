### A. Confirm or refute the prediction for distributed L with the PIC code

This comes first. Erik wants the distribution in L in the article, and the outcome changes the
abstract: if the PIC code confirms C4, the core is a property of clouds with almost equal
angular momenta.

**A0. Check the derivation independently.** Derive again Eqs. (Kernel) and (ReducedL) of the
notes (average of |D - Re[(zeta_i - zeta_j) e^{i kappa_0 t}]/sqrt(kappa_0)| over the fast
phase). The unit tests of 2026-11-11 were run interactively and are not saved: kernel formula
against a direct average (4e-11), C routine against numpy (5e-7), equal L against the fixed-L
routine (3e-9), conservation of the energy. Save them as a script.

**A1. Build and verify `VlasovPoisson_PIC_sp`.** `make`, then `verificacion/correr.sh` must
pass 16 of 16.

**A2. Driver.** Suggested: `VlasovPoisson_PIC_sp/reproducir/scripts/nube_L.py` with the steps
`preparar`, `correr`, `analizar`, `tabla`, after the pattern of `bulto.py`. It should import
`reducido.reticula_L` from the other repository, so that the PIC code and the model use the
same particles.

- Initial data through `state = checkpoint`: one line `r p_r L f` per particle, exactly
  `Nrc*Npc*Nlc` lines. The code normalizes the mass with `sum(f*L)`, so the mass of a particle
  is proportional to f L. Write f = F_0(Q,J) exp(-(L-L_0)^2/s_L^2), which is the weight
  returned by `reticula_L` divided by L.
- Keep `lminc < lmaxc` also when there is a single value of L: `dlc = (lmaxc-lminc)/Nlc`
  enters the normalization. It cancels, but it must not be zero.
- (r, p_r) from (Q, J, L) with the isochrone map for the L of each particle
  (`tools/aa_numerico_L.py` has both directions; `bulto.dato_isocrono` does it for fixed L).
- Remaining parameters as in `reproducir/corridas/12_demo_eta/bulto__B021.par` of the fixed-L
  repository: `dr = 0.1`, `rmax = 20`, `courant = 1.0` (time step 0.05), `Nt = 200000`,
  `bsplineorder = 1`, `integrator = yoshida4`, `BGtype = Isochrone`, `eps = 0`, output every
  200 steps. Check the time step that the code reports: in `_sp` the bound at the pericenter
  can change it.
- The lattice in L has N_L midpoints in |L - L_0| <= 2 s_L. Its recurrence time is
  2 pi N_L/(4 s_L |dOmega/dL|) with |dOmega/dL| = 0.0754. N_L >= 480 s_L keeps it beyond
  t = 10^4. Note that the Gaussian of the code is exp(-(L-L_0)^2/s_L^2), so
  sigma_L = s_L/sqrt(2).

**A3. Port the analysis.** For each snapshot compute (Q, J) of every particle in the
potential of that instant with its own L (class `MapaAA` in `tools/aa_numerico_L.py`;
`tools/hk_numerico.py` shows how the self potential is taken from the snapshot). Then
zeta = sqrt(2J) e^{iQ} and the measures of `reducido.diagnosticos`, with particle mass
proportional to f L:

- h_1 = sum m e^{-iQ}/sum m, mean of |h_1| over 10 <= t/tau_1 <= 20;
- m02: mass fraction with J < 0.2 sigma_J, mean over t >= 20 tau_1;
- rho_c: density in J < 0.025 sigma_J in units of the mixing bound F_max-hat;
- m_c: mass fraction in the disc of action 0.05 sigma_J about the density maximum in the
  zeta plane;
- a_c = |zeta_c|/sqrt(kappa_0) for the particles of that disc at the last snapshot;
- D: deviation of the potential of the gas (`bulto.campo_particulas`).

The measures must be taken in the zeta plane, not in the (r, p_r) plane as in the article:
with distributed L each particle has its circular orbit at its own radius R(L), and
|L - L_0| = 0.08 moves it by 0.33, which is the size of the ellipse (CoreEllipse), a = 0.38.
The mixing bound does not depend on the spread in L: a gas that is mixed at fixed (J, L) has
rho_c <= 1 and m_c <= m_mix = 0.042. With distributed L, |h_1| also decays by free mixing in
L. Judge the presence of a core by rho_c and m_c, and its oscillation by a_c.

**A4. Consistency run (cheap; first).** Run `_sp` with the particles of the fixed-L run
`B021` (`exe/demo_eta/bulto/ic/B021.dat`, columns r, p_r, f; add L = 2) and compare with
B021: |h_1| = 2.08e-2, m_c = 0.115, D = 3.6e-4, minimum of a_c 0.012 at 10 tau_1. Compare also

t <= 5 tau_1 and the late measures agree within 5 %. If not, find the difference between the
two codes before going on. Do not use M_gas/M >= 0.025 for this test: there a_c(t) differs
by 20 to 70 % between lattices in the fixed-L code itself.

## 7. Known pitfalls

- `grep` is a wrapper that returns nothing in some directories: use `command grep`. A
  foreground `sleep` is blocked. A command that exceeds 600 s is moved to the background:
  launch long jobs with a chain script (`exe/demo_eta/bulto/cadena_tanda5.sh` is the pattern),
  with `date` between runs and `FIN` at the end.
- Erik's plan reaches its usage limit during long turns. Write notes and commit early.
- Wall time on the laptop varies by a factor 2 with 4 threads.
- a_c from the particles selected at the last snapshot is not reliable in long runs; use
  `reducido.centro_instantaneo`.
- The pair sum in double precision is ten times slower than in single precision (error 1e-6).
  With distributed L only the single-precision sum exists.
- The tables of the notes are macros (`\TabL`, `\TabReferencia`, ...) loaded in the preamble;
  an `\input` inside a `tabular` fails. `main.pdf` of each document is added with `git add -f`.
- The series `hk?.tl` written by the codes carry the factor a_n of the test function and use
  the map of the external potential. The analysis of the cloud does not use them.
